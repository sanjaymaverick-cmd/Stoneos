# Finance and commercial testing users

Use `createFinanceAgent(ctx)` from `scripts/testing/finance-scenarios.mjs` only with the orchestrator's explicitly authorized, freshly created test factory. The default is a fresh local database. The user subsequently authorized Oracle testing; that requires an exact new test-factory allowlist and preservation verification for every existing factory. Never reuse the owner's actual operating factory. Every party is explicitly synthetic. Passwords and tokens must not appear in reports.

`ctx.request(role, method, path, body, options)` returns `{status, ok, body}`, records evidence and rejects unexpected HTTP results. `ctx.check(name, passed, details)` records independent invariant results. The caller supplies `runId`, distinct role sessions and `report`.

Call `setup()`, then `runMonth({month,date,slabIds,rawBlockIds,producedSqft,targetSalesSqft})` for October 2025 through September 2026, then `finish()`. Production provides polished 40 sqft slab IDs. Unsold manufactured stock carries forward. Monthly gross sales rotate 80,000 / 90,000 / 100,000 sqft, with a single 40 sqft return reported separately. Orders contain at most 100 pieces to keep existing interactive transaction limits realistic.

Owner reviews insights, GST settings and follow-up promises, invoices, collects partial/full payments, pays costs and payroll, and proposes spending intake. Sales users quote, reserve, pack, dispatch and record unbilled cash. Accountants read dues and Money reports; their expense writes and GST reads are expected to be denied. Managers independently approve payroll and intake under their current compatibility mapping to owner. Auditors check trial balances and cannot create expenses. Operators cannot confirm intake or create workers. Supervisor records attendance. Persisted roles are separate identities; current compatibility mapping makes manager/admin effectively owner and sales/inventory effectively supervisor. A passed request must not be described as evidence of narrower permissions than the application actually implements.

Coverage includes registered and consumer customers with addresses, local/interstate GST, cash/bank/UPI/NEFT receipts, dealer credit, partial payment, separate billed/cash companion orders, reservation/payment/cash retry invariants, rejected overpayment, returns/credit notes, direct finished purchases with GST and unpaid supplier balances, general expenses, attendance/half day/overtime, payroll segregation and repeat payment, balanced trial balance, GST head reconciliation, party reports, analytics, exports, books/rokad, files, intake confirmation/rejection, review-only journal proposal, Tally import and explicitly mock statutory documents.

The complete staffing cost is not modeled: four named synthetic workers each have 22 attendance dates per month. Electricity, diesel and maintenance values are scenario assumptions rather than researched operating benchmarks. Consumable buying and movement must be supplied by the production agent; an expense is not proof of an integrated supplier purchase bill.

Do not claim full feature proof from HTTP 200 alone. HTTP success proves route execution; balance, replay, area, direct stock and payroll checks prove their stated invariants. Download workbook contents, stock movement reconciliation, tenant isolation, individual voucher balancing and UI role workflows require the orchestrator/security/UI checks. Live OpenAI and statutory submission remain unverified. Later supplier payable settlement, complete COGS, arbitrary Khata cutover and a native combined bill-plus-unbilled-cash document remain gaps.

Finish probes continue independently after a failure, recording each route result and failed feature in `report.boundaries`; dependent confirmations require a returned draft ID. An unconfigured OpenAI answer request is expected to return 503 and remains partial. Daily DPR is checked for 22 September 2026: 110 pieces passed through grinding, resin and polishing should not be presented as 330 distinct finished pieces. The known fixture buys 44 rough blocks monthly, each taxable ₹200,000 at 5%: ₹440,000 rough input GST plus ₹3,780 on the finished receipt equals ₹443,780 expected monthly credit. A mismatch must be recorded, not compensated with invented journals.
